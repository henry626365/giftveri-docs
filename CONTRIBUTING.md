# Contributing to the documentation

Keep proposed changes focused on a specific guide, a current product behavior or an improvement to a reader's task.

## Before proposing a change

1. Check the relevant page on the official product website.
2. State the client version, brand and region to which the change applies.
3. Distinguish a documentation correction from an independently verified client result.
4. Include a public source where a feature, package or support statement can be checked.

Avoid treating a listed brand, a development-build flow or a published package as evidence that every real-card operation works.

## Examples and images

Use invented labels and demonstration data. Redact card numbers, PINs, passwords, verification codes, tokens, private account information and CSV contents before sharing material publicly.

Product illustrations should be accurate for their stated version and clearly identify demonstration data. Do not replace a product screenshot with an illustration that implies an unverified function.

## Scope of a documentation change

Keep software package distribution and version details linked to the official source. Do not commit application executables, account exports or session files to this documentation repository.

For product assistance, begin with the [official features and help page](https://www.giftveri.com/en/help).
